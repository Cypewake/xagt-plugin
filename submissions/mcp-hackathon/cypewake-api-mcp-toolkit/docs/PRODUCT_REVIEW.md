## 3. 三透镜发现

### 产品（Product）
- **问题价值（高）**：把"任意 OpenAPI 规格"转成"Agent 可直接调用的 MCP 工具"，是 Agent 开发者的真实刚需。市场已有同类商业产品，说明需求成立。
- **战略契合（极佳）**：直接对齐官方主题 "Build → Verify → MCPize → Monetize / Move from API to MCP"。不是硬凑，是原生契合。
- **差异化（强）**：比最低 MVP 多了「真实断言验证、四阶段可视化走查、真实用量计量→出账」。这是相对"7 工具裸交付"的实质超越。
- **MONETIZE 阶段的真实性（需明确）**：计量是真实的（记录调用量、折算账单），不是打印价目表。但它是"作品集叙事"，真实商业化需接入支付——这点要在文档里讲清，避免被误读成"虚的"。

### 用户（User）
- **目标用户**：Agent 开发者（真正用的人）、评委（验收的人）。
- **触发时刻**："我有一份 API 规格，想变成 MCP 工具。"
- **摩擦点**：需 GitHub 账号（本地零部署即可复核，无需公网）。走查页已显著降低评委的验证摩擦（一键跑完整流水线）。
- **失败恢复**：生成代码内置 3 次重试；注册表/计量原子写入，损坏留档不静默清空。
- **边界用户**：匿名/无 GitHub 用户无法完成 PR 提交（属赛事机制，非产品缺陷）。

### 技术（Technical）
- **依赖**：fastmcp / httpx / pyyaml，全部免费、免密钥。运行成本为零。
- **可靠性**：测试套件 + 原子写入 + SSRF 逐跳校验重定向。
- **隐私**：仅落地 registry.json/usage.json（本地文件），无外部数据上报。
- **可维护性**：core 单文件 ~900 行偏重，但职责清晰；fastmcp_kwargs 兼容层有实测依据，注释完整。
- **可回退**：纯确定性规则/模板生成（非 AI 黑盒），输出可人审、可复现、可调试——这比"AI 自动写"更安全可控。
